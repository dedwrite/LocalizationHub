# v0.7 Game Text Extraction — Architecture

## Goal

Extraction-first game text ingestion for Unreal, Godot, and Unity. The pipeline
discovers localization resources, extracts translatable text, separates it from
technical strings, protects format/placeholder content, and retains
speaker/listener/gender/context with provenance — all read-only.

## Responsibility split

- **`packages/core/src/extraction`** — the normalized model, classification,
  protection, context/conversation inference, engine detection, structured-data
  analysis, review aggregation, and the read-only scan orchestrator. Pure,
  browser-safe, fully unit-tested. No engine-specific binary I/O here beyond the
  text/buffer formats that are parseable deterministically.
- **`packages/core/src/tokens`** — engine-aware token profiles (generic, godot,
  unreal, unity). Extraction reuses these for protected segments.
- **`frontend/src/extraction`** (desktop) — the Scan Game flow, the Extraction
  Review UI, the Source/Origin inspector panel, and the optional external-tool
  adapter. Only the desktop does filesystem/archive/binary work.
- **`src-tauri/src/scan.rs`** — a read-only directory walk that returns candidate
  localization files (bounded, extension-filtered).
- **Web** — consumes only the normalized project (context, provenance,
  classification, protected tokens). It never parses engine archives.

## Normalized model

Every engine adapter produces one `ExtractionResult` containing
`ExtractedEntry[]`. Each entry carries:

- stable `id` (structural, distinct from source text), `key`, `namespace`, `order`
- `sourceText`, `sourceLocale`, optional `existingTranslation`, `pluralVariants`
- `classification` + `classificationConfidence`
- `context` (speaker, listener, genders, scene, conversation, prev/next, notes)
- `origin` (`SourceLocator`) for traceability
- `protectedSegments` + `protectionProfile`
- `rawMetadata` (safe normalized extras)

Every inferred context field carries `FieldProvenance` (source + confidence) so
heuristic output is never presented as guaranteed engine metadata.

## Classification (the anti-grep)

`classifyString` scores a string on positive natural-language evidence and
negative technical evidence (GUID, hash, path, identifier, enum, locale code,
URL, resource reference). A structural hint (known UI field, dialogue schema,
table membership) suppresses identifier/enum penalties so single-word labels
like "Settings" classify as UI. Binary printable-string scanning is NOT a
primary parser for any known format.

## Protection

Protected segments are produced by the engine-aware token profiles. Unreal adds
plural/gender/Hangul modifiers and empty inline closing tags; Unity adds Smart
String nested selectors and TextMeshPro tags. Validation after translation is
provided by the existing token-validation layer.

## Context intelligence

`contextInference` recognizes speaker/listener/gender/scene/text fields via
aliases and supports user-defined field mappings for custom schemas. Gender is
only set from explicit engine/field/schema data — never inferred from a name.
`conversationInference` groups by explicit conversation IDs and links
previous/next only within a shared conversation.

## Engine adapters

See `v0.7-engine-compatibility.md` for the honest per-format matrix. Each
adapter is extraction-only; nothing writes back into original game files.

## Immutability

The scan orchestrator has no write path. Tests assert source content is
byte-identical after extraction.

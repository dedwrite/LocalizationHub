# LocalizationHub v0.6 Web Parity

## Architecture

The v0.6 browser application remains a separate Vite React surface. `website/src/appApi.ts` provides same-origin bearer-token transport for authentication, Cloud Projects, team membership, workflow, comments, assignments, activity, restore, and verification. Tauri-only filesystem and dialog behavior stays in the desktop frontend.

The browser imports pure domain behavior from `@localizationhub/core` for project statistics, protected-token validation, metadata, Translation Memory, parsing, and exporters. Browser-local persistence uses IndexedDB and never stores account bearer tokens.

## Routes

- Public: `/`, `/download`, `/privacy`, `/terms`
- Cloud app: `/app`, `/app/login`, `/app/register`, `/app/projects`, `/app/projects/:projectId`
- Browser-local mode: `/app/local`

The existing gateway serves direct nested app routes through the website SPA while preserving `/health`, `/verify-email`, `/api/*`, favicon ownership, and WebSocket upgrades.

## Cloud workspace

The browser Cloud editor supports real project loading, entry search and filtering, translation editing, workflow statuses, revisioned saves, protected-token warnings, statistics, comments, assignments, history/activity, restore, team membership management, glossary display, Translation Memory suggestions, and a collaboration host surface. Backend permissions remain authoritative; viewers are read-only and member operations are owner-only.

The existing protocol version 2 and one-time ticket architecture are reused for browser collaboration. The browser WebSocket URL is same-origin secure WebSocket connectivity in production.

## Browser-local mode

Users can import JSON, CSV, and gettext PO files through native browser file APIs. Parsing and export use core implementations. Translation edits, search, navigation, validation, local save, recovery after refresh, and export remain local until the user explicitly chooses a Cloud workflow.

## Mobile and tablet UX

Desktop/tablet uses a multi-pane entry/editor/tools layout. Phone widths use a single-column translation-first layout, touch-sized controls, compact tool tabs, and fixed bottom navigation. Tool surfaces provide comments, assignments, history, team, glossary, Translation Memory, and collaboration without requiring hover.

## Security and privacy

- Same-origin API requests use bearer headers.
- Bearer tokens are not placed in URLs or rendered in the UI.
- WebSocket tickets are short-lived and separate from bearer tokens.
- Cloud authorization remains server-side.
- Local browser files are not uploaded automatically.
- Project/comment text is rendered as React text, not raw HTML.
- No production infrastructure configuration or credentials are included here.

## Deliberate omissions for release hardening

- Dedicated browser end-to-end/device automation.
- Full desktop/web simultaneous-session acceptance against a deployed environment.
- Browser project deletion and account deletion, which are absent from the backend contract.
- Rich browser glossary editing and full tag editor UI beyond document-backed controls.
- A complete browser join/resume collaboration controller equivalent to the desktop session UI.
- Final accessibility audit with assistive technology and formal performance budgets.

## Tests

Focused website tests cover editor permissions, immutable translation/status updates, revision conflict state, combined filters, and JSON local import/export behavior. The consolidated release gate includes website and desktop builds, core tests, collaboration-server tests, backend syntax, and Cargo checks.

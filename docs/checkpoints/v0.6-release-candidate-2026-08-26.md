# LocalizationHub v0.6.0 Release Candidate

## Release identity

- Version: `0.6.0`
- Product: Web App & Mobile Translation
- Scope: browser Cloud Projects, mobile/tablet translation, browser-local translation, and desktop/web interoperability.
- Production deployment and final release publication remain pending.

## Architecture and routes

The browser app remains a separate Vite React application with same-origin bearer-token API calls. Tauri-only filesystem and dialog behavior remains desktop-only. Pure parsing, exporting, metadata, statistics, protected-token validation, and Translation Memory logic use `@localizationhub/core`.

Routes include public `/`, `/download`, `/privacy`, `/terms`; browser Cloud routes `/app`, `/app/login`, `/app/register`, `/app/projects`, `/app/projects/:projectId`; and browser-local `/app/local`. The existing gateway preserves backend ownership of `/api/*`, `/health`, `/verify-email`, favicon routes, and WebSocket upgrades.

## Feature set

The web workspace provides Cloud Project listing/creation/loading, entry search and filtering, translation editing, workflow states, statistics, protected-token warnings, comments, assignments, history/activity, restore, team controls, glossary and Translation Memory guidance, and protocol-v2 collaboration host/join/reconnect controls.

Browser-local mode supports JSON, CSV, and gettext PO import/export, protected-token validation, editing, search, and IndexedDB recovery. Local file content is not uploaded automatically.

## Mobile and installability

Desktop/tablet uses a multi-pane workspace. Phone layouts use a translation-first single column with touch-sized navigation and tool surfaces. The website includes an installable manifest using existing project branding. No service worker is used, avoiding stale authenticated API or Cloud data caching.

## Compatibility and security

Collaboration remains protocol version 2 with one-time tickets and same-origin secure WebSocket connectivity. Bearer tokens are sent in headers, not URLs or UI. Server-side permissions remain authoritative. Comments and project content are rendered as text. The built website bundle passed a scan for database URLs, Resend keys, bearer-token patterns, staging hosts, and localhost runtime leakage.

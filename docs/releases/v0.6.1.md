# LocalizationHub v0.6.1

**Release Date:** 2026-08-27

## Web Workspace Parity & Translator Experience

The browser workspace now feels like the same LocalizationHub product as the desktop application — a dense, translator-first workspace rather than a sparse web page.

### Workspace layout

- Three-pane layout: **Entries** (left), **Translator** (center), **Inspector** (right).
- Resizable Entries and Inspector panels (drag handles), persisted locally.
- Collapse controls for Entries and Inspector, plus a Focus Mode that expands the editor.
- Layout preferences stored locally (never in Cloud project metadata).

### Inspector

- Tabs: Workflow, Quality, Comments, Assignments, History, Tags, Translation Memory, Glossary.
- No horizontal scrolling to reach tabs — tabs wrap on narrow viewports.
- Comments (add/resolve), Assignments (per-entry), History (chronological + restore with confirmation), Tags (assign/remove + create), Translation Memory (apply suggestions), Glossary (issues + terms).

### Machine Translation Reference (Web)

- Gemini / Google AI Studio provider, called directly from the browser.
- Session-only API key held in memory — never persisted, never sent to the LocalizationHub backend, never stored in project data.
- Source/target language selection with swap, translate action, loading/error states, clear, and copy result.

#### Gemini models & performance

- **Gemini 3.5 Flash-Lite** — fastest, the default.
- **Gemini 3.6 Flash** — balanced speed and quality.
- **Gemini 3.7 Flash** — highest quality.
- Lower-latency thinking configuration so translations return quickly.
- Provider errors are surfaced inline without interrupting the editor.

#### Browser credential UX fix

- The API key field is a visually masked text input with a Show / Hide toggle (not an HTML password field), which prevents browser credential managers from autofilling it.

### Entry list parity

- Counts: total, translated, untranslated, needs-review, errors, warnings.
- Filters: All, Untranslated, Draft, Translated, Needs Review, Approved, Errors, Warnings, Has Comments, Assigned to Me, Has Tags.
- Per-row indicators: workflow dot, QA issue, comment count, assignment, selection state.
- Checkbox bulk selection with bulk workflow actions (set status across selection).

### Editor

- Source panel with protected-token highlighting, copy source, context/notes.
- Direction-aware translation editor (LTR/RTL), inline QA warnings, workflow status controls.
- Jump to Entry by number with bounds validation.
- Previous/Next Untranslated navigation.

### Toolbar, save, and keyboard

- Toolbar: Home, Collaboration, Token Profile, save state, Save, Search & Replace, Overview, panel/focus controls.
- Save states: Saved / Unsaved / Saving / Failed, with debounced autosave for Cloud Projects (revision-conflict safe).
- Keyboard: Ctrl+S save, Ctrl+Enter commit-and-advance, Alt+Down/Up next/prev entry, Ctrl+F search, Escape dismiss.

### Cloud save reliability

- Draft updates are resolved against the latest project state immediately, so saves always serialize a valid project object rather than a stale closure.
- Single-flight saves never lose edits made while a save is in flight; newer edits save against the incremented revision.
- Manual Save and debounced autosave both round-trip through the same validated path.

### Legacy project compatibility

- Cloud Projects created with Project V1 or V2 open normally and migrate in memory to the current Project V3 format on next save.
- Migration preserves entries and existing workflow metadata; the app reports when a legacy project is loaded and will be upgraded.

### Projects page & New Project

- Project cards show name, role, source file, revision, entry count, translated %, member count, and last updated.
- Project search, loading/error/empty states.
- Branded New Project modal (no native `window.prompt`) with optional JSON/CSV/PO import into a new Cloud Project.

### Performance & accessibility

- Windowed virtualization for the entry list (10k+ entries smooth).
- Responsive across 360–1920px with no horizontal document overflow.
- axe: 0 serious, 0 critical on critical workspace views.
- Viewer remains read-only; server remains the authority.

## Mobile Workspace Redesign

The phone experience was rebuilt as an intentionally designed mobile app rather than the desktop layout stacked vertically.

### Mobile navigation

- A bottom navigation of **Entries**, **Editor**, and **Tools** separates the primary translation flow from secondary tools.
- Entries: project progress, search, filters, and the entry list.
- Editor: the current entry — source, translation, workflow, and entry navigation.
- Tools: the full Inspector plus Project Overview, Search & Replace, and Collaboration.
- Selecting an entry returns you to the Editor; thumb-friendly targets and clear selected states throughout.

### Touch-first editor

- Compact entry header with key and workflow state.
- Readable source card with a Copy action.
- Auto-growing translation field with a 16px font (no iOS zoom-in on focus).
- Workflow status (Draft / Translated / Needs Review / Approved) as comfortable buttons below the translation.
- Previous / Next and Next Untranslated navigation.
- Save stays visible in the header with clear Saved / Saving / Unsaved state, plus debounced autosave.

### Entries and filters

- Compact progress summary (entries, remaining, translated, review, errors).
- Search plus primary filter chips (All, Untranslated, Translated, Needs Review, Errors) and a "More filters" control for the rest.
- A dedicated selection mode keeps checkboxes out of normal browsing.

### Projects and auth

- Simpler mobile Projects page with compact cards and a clear New Project action.
- A Cloud / Local switcher for browser-local workflows.
- Login and Register stay clean with correct browser autofill semantics.

### iPhone Safari behavior

- Inputs sized to prevent auto-zoom; dynamic viewport and safe-area insets keep content and navigation visible.
- LTR/RTL direction applied to source and translation independently.
- Nothing important hides behind the Safari toolbar or home indicator.

### Testing

- WebKit (Safari) Playwright coverage is kept permanently (iPhone and iPad projects) alongside Chromium; Chromium viewport emulation is no longer reported as Safari acceptance.

### Existing functionality

- Cloud Projects, collaboration, comments, assignments, history, workflow metadata, glossary, translation memory, and browser-local workflows continue to work as before.
- Existing Admin and security functionality remains intact.

## Important fixes

- Resolved a production crash where opening the Web App with no valid session showed "Workspace unavailable" instead of Login.
- Hardened browser auth restoration so corrupt or stale local storage never breaks startup.
- Improved the error boundary to surface real diagnostics in development while keeping a friendly fallback in production.
- Stopped Chrome credential autofill from hijacking the Machine Translation API key field.
- Fixed a stale Gemini model reference; the web Machine Translation now uses supported current models.

## Final testing

- Builds: website and desktop frontend both compile cleanly; the Tauri desktop checks compile.
- Unit tests: `@localizationhub/core` and website logic pass (106 tests).
- Server tests: collaboration-server passes (85 tests).
- Playwright (Chromium): all workspace, admin, legacy, and save suites pass across desktop and phone/tablet viewports.
- Playwright (WebKit): iPhone and iPad Safari projects pass the workspace, mobile workflow, and boot regression suites.
- Performance: virtualized entry list holds up for 10,000+ entries.
- Accessibility: no serious or critical axe violations on critical workspace views.

## Scope

No game extraction, injection, Godot PCK, Unreal archive, LOCRES, or engine integration. Those remain v0.7 work.

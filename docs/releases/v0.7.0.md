# LocalizationHub v0.7.0

v0.7.0 introduces **Game Text Extraction**: turn a raw game folder into a
LocalizationHub localization project, read-only, with rich dialogue context and
protected-token preservation.

## Game Text Extraction

The new workflow turns a supported game project folder into a translation-ready
LocalizationHub Project:

1. **Game Folder** — choose a Godot, Unreal, or Unity project folder.
2. **Scan** — LocalizationHub detects the engine and discovers localization
   resources.
3. **Extraction Review** — review, filter, and map context before anything is
   created.
4. **Project** — create a LocalizationHub Project and start translating.

Extraction is **read-only**: your source game files are never modified.

## Godot

- **PCK workflow** — extract `.pck` archives with GDRE-assisted tooling.
- **Native parsing** — CSV, gettext PO/POT, `.tscn`/`.tres` scenes, and `.gd`
  script text.
- **INKB dialogue** — native story dialogue extraction with speaker resolution
  and cross-locale line alignment.
- **Player choices** — timed choices are extracted where structurally proven.
- **Locale aggregation** — multi-language files collapse into one logical entry
  with locale variants, never one duplicate per culture.
- **Derived-copy handling** — binary resources are converted read-only, leaving
  the original untouched.

## Unreal

- **PAK / IoStore workflow** — unpack with verified external tools.
- **LOCRES / LOCMETA** — native readers for compiled localization resources.
- **Encrypted archives** — a user-supplied AES key can be provided for
  encrypted archives when the external tool supports the archive.
- **Precision filtering** — engine and editor stock is excluded from the default
  project, keeping the player-facing game text.
- **Structured assets** — FText/DataTable/DialogueWave JSON where supported.

Some newer UAsset versions remain partial (the verified dumper covers an older
engine generation).

## Unity

- **UnityPy-assisted extraction** — serialized assets and `.bundle` files via a
  UnityPy helper.
- **TextAsset** — JSON/CSV/Ink/Yarn/XML/YAML payloads routed to the correct
  adapter.
- **MonoBehaviour / ScriptableObject** — structured extraction.
- **Unity Localization** — string tables with source-locale detection.
- **Dialogue System** — `MasterDialogueDatabase` extraction with speaker,
  listener, and locale variants.
- **Precision filtering** — schema and tooling fields are skipped.

Stripped type trees remain limited: assets whose type tree was stripped at
build time are inventoried but not fully extracted.

## Extraction Review

A desktop review workspace with:

- virtualized entries and a searchable **Sources** panel,
- a maximizable **Diagnostics** panel,
- **Context Mapping** (including an Ignore role),
- locale/source switching with a preview,
- filters for runtime vs tooling content,
- protected-token preservation, and
- **Create Project**.

## Generic Open File Context

Opening an ordinary JSON/CSV/PO file preserves explicit dialogue context when
it is present: speaker, listener, speaker/listener gender, pronouns, scene,
conversation, multiple listeners, voice, and portrait. Genders and pronouns are
only ever read from explicit fields — never guessed from names or language.

## Performance / Reliability

- Responsive scans with chunked batch IO.
- Failure isolation: one unreadable archive never aborts the whole scan.
- Cancellation during long scans.
- Read-only source safety by construction.

## Known limitations

- Newer Unreal UAsset versions are not covered by the verified external dumper.
- Unity assets with stripped type trees are inventoried but not fully extracted.
- Godot `OptimizedTranslation` keys are one-way hashes; values can be recovered
  but keys require a full-project recovery pass.
- Some Ink choice forms are structurally ambiguous and are not auto-extracted.
- Encrypted archives require a valid user-provided AES key; keys are never
  brute-forced.

Extraction is read-only and extraction-first; no engine reinjection is exposed.
